# New API SaaS — 第二阶段规格（可真正使用）

在已交付的单进程多租户基础上继续开发。硬约束不变：单进程 + `tenant_id`、禁止每租户 worker、少改 relay/渠道核心、密钥不进仓库。

## 目标
把平台做成可真正运营的 SaaS 控制台：完整网站管理员后台、清晰区分站长与普通用户、规范权限与套餐开通、平台级兑换码，以及 Lite / Standard / Pro 合理功能差。平台鉴权与后台交互参考 New API 空间内已有能力（会话、2FA/安全验证风格、管理员权限粒度、兑换码管理体验），但作用域在**平台层**，不要和空间内 New API 用户体系混为一谈。

## 角色与权限
1. **平台站长（admin / root）**
   - 用户管理：列表、搜索、启用/停用、重置/要求改密、提升/取消管理员（至少一个站长保留）
   - 空间管理：全站空间列表、停用/恢复、改套餐、查看用量与归属
   - 套餐管理：查看/调整三档默认限额与能力开关（或至少种子数据+管理 UI）
   - 兑换码：生成、批量、作废、查询使用记录
   - 审计：关键操作写入平台审计（开通套餐、改角色、发兑换码、停用空间等）
2. **普通平台用户（user）**
   - 注册/登录/改密/登出（沿用并加强现有安全：Argon2、会话、CSRF、限流）
   - 仅管理自己的空间；用兑换码自助开通/续期套餐；查看自己的用量与套餐
   - **不能**进站长后台，不能改别人空间/套餐

UI 必须明显分区：登录后普通用户看「我的空间」；站长另有「管理后台」导航（独立路由如 `/platform/admin/*`），不要把管理按钮散落在普通卡片上凑合。

## 套餐：Lite / Standard / Pro
增加 **Standard**，三档并存（迁移兼容：旧 Pro 保留；无 Standard 的库 seed 插入）。建议默认：

| | Lite | Standard | Pro |
|---|---|---|---|
| 月请求 | 1,000 | 20,000 | 100,000 |
| 用户 | 5 | 50 | 1,000 |
| 令牌 | 20 | 200 | 10,000 |
| 渠道 | 3 | 20 | 100 |
| 可移除平台页脚 | 否 | 否 | 是 |
| 自定义品牌/站点名展示 | 基础 | 是 | 是 |
| 兑换码开通 | 是 | 是 | 是 |
| 人工开通 | 站长可 | 站长可 | 站长可 |
| 空间数/用户（平台侧） | 默认每用户可建 1 个空间 | 可建 3 | 可建 10（可用能力矩阵配置） |

能力用 `capabilities` JSON 扩展（如 `remove_platform_footer`、`custom_branding`、`max_workspaces`），前后端强制校验。数字可在种子中调整，但三档必须有清晰差异。

## 兑换码（平台级）
- 表：`platform_redemptions`（code、plan_id、duration_months、status、max_uses/used、expires_at、created_by、redeemed meta）
- 站长：生成（单个/批量）、禁用、列表筛选
- 用户：在平台控制台输入兑换码 → 给**选定空间**开通/续期对应套餐（到期顺延或覆盖策略写清并实现一种，推荐：未过期则从当前到期顺延，否则从现在起算）
- 安全：限流、一次性/次数限制、审计、禁止枚举（统一错误文案）
- **不要**复用空间内 `model.Redemption` 额度兑换逻辑冒充套餐兑换；可参考其 UX/事务风格，但是平台新模型

## 套餐开通规范
- 路径：站长人工开通、用户兑换码开通；第一版仍可不做在线支付
- 开通写入 `plan_assignments`（或等价）含来源：`manual` / `redeem`
- 到期/停用拒绝访问；升级立即恢复限额
- 站长 UI：选空间 + 套餐 + 月数；确认与结果反馈完整

## 后台体验（对照 New API）
- 管理列表：分页、搜索、状态筛选、空态/加载/错误
- 危险操作二次确认（Dialog/ConfirmDialog）
- i18n：至少 en + zh
- 复用现有 shadcn 组件与平台 CSRF/会话契约
- 可选增强（有余力再做）：站长登录二次确认敏感操作、会话列表/撤销其他会话（已有改密撤会话可扩展）

## 验收清单
1. 普通用户看不到站长后台路由与 API（403）
2. 站长可管理用户/空间/套餐/兑换码
3. Lite/Standard/Pro 限额与能力差生效（页脚等）
4. 兑换码可为空间开通/续期；作废码不可用；审计可查
5. 构建与测试通过；STATUS 与 PR 说明完整
